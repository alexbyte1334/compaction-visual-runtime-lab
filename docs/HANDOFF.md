# 公司电脑接续开发

先按 README Clone、安装、warmup、运行 pytest 与 compare。不要把 .venv 从 macOS 复制到 Windows；重新安装依赖。首次准备需要网络；`.token-cache/` 缓存缺失时程序会要求先准备，不会默默用字符数替代 Token。

## 第一轮：理解自己要讲的案例（约 1 小时）

- [ ] 单步走完正常实验；找到真实失败日志和对应 source_id。
- [ ] 恢复后检查一行补丁与 83 passed；独立修改 fixture 故障，观察当前脚本 Worker 的适用边界。
- [ ] 运行丢失约束、伪造证据、超预算三种故障；确认原状态保留、恢复按钮禁用。
- [ ] 改变 target；不要把某次默认值的压缩率当成固定结论。
- [ ] 将亲自复跑的观察写入自己的分享笔记，明确合成案例与实际工作案例的区别。

## 第二轮：接入真实 API（本次没有接入）

扩展点是 `lab.providers.CompactionProvider.propose(request) -> dict`。先实现一个返回同一决策 schema 的模型 Adapter，保留 RuleProvider 用于测试。不需要改 UI 和 Runtime 的信任边界。

- [ ] 选择接口和模型，核对当时官方文档；用户自己配置本地环境变量，勿把密钥写入仓库。
- [ ] 请求输出受约束的结构化数据；输出仍要经过 validate_proposal 和 Runtime.validate。
- [ ] 为网络错误、拒绝响应、schema 错误、超时和用量设上限；失败时不提交上下文。
- [ ] 保存经脱敏的实际请求、响应、模型名、配置、用量、耗时与内容哈希；严格区分真实录制和人工 fixture。
- [ ] 单独提供 replay 模式，按请求哈希匹配；回放不计为现场 API 成功。
- [ ] 替换 scripted Worker 进行真实模型继续任务实验；按相同输入、相同工具权限和同一验收测试比较。

如果选择 OpenAI 原生 compact 接口，应作为独立实验模式：它返回的是官方不透明状态，不符合本项目明文 decisions schema。不能把 opaque 内容伪解析成 KEEP/COMPRESS/DROP；官方输出要按官方文档用于后续请求。不要为了显示中间阶段而虚构模型内部过程。

## 第三轮：让分享结论更稳

- [ ] 增加约束在不同位置、要求被修订、重复工具结果、过时文件、长日志等变体。
- [ ] 每个策略/案例至少重复 3 次；新增“简单摘要”基线时也使用相同任务测试。
- [ ] 指标同时报告保留率、真实任务完成率、失败关闭率、Token、模型输入输出用量与延迟。
- [ ] 增加多轮压缩与跨代证据索引，验证重复压缩是否累积丢失事实。
- [ ] 需要跨进程恢复时再做 checkpoint、版本冲突和工具副作用台账；不要仅凭 JSON 文件存在宣称恢复可靠。

## 分享材料检查

本仓库只包含新建的合成源码与合成测试标识。准备加入工作案例时，先确认是否允许使用；移除雇主/客户名称、内部地址、路径、业务数据、凭据和原始日志。不能用“脱敏”标签代替实际内容检查。未经许可的材料不要放入 GitHub，包括私有仓库。

当前只是初步框架，不需要先引入 LangGraph、MCP、向量库、多 Agent 或新服务才能继续开发。
